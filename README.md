# 外贸客户信息整理工具

一个简洁的浏览器客户数据工作台：将不同格式的外贸客户表映射到统一结构，人工校对，再导出 Excel 或 CSV。

2.0 使用 React、TypeScript、Vite、Ant Design 和 AG Grid Community 重构。蓝青色工作台包含客户分类卡片、可编辑资料表，以及导入映射、字段管理和原始内容侧边面板。数据处理规则与界面分离，继续在浏览器本地处理资料。

## 功能

- 批量选择或拖放 XLSX、XLS、CSV、TSV、ODS，单文件上限 20 MB。
- 每份文件独立选择工作表、表头行和字段映射；自动识别常见中英文表头。
- 客户名称（兼容原“联系人”）、公司名、邮箱为固定字段，不可删除；电话、国家 / 地区、产品需求、网站、备注等可删除。
- 在“字段设置”中新增自定义字段，例如采购数量、客户等级。映射、表格编辑、搜索、模板和 Excel/CSV 导出同步使用当前字段。
- CSV / TSV 支持 UTF-8、GB18030 / GBK、UTF-16 LE 编码选择。
- 编辑单元格、新增客户、批量删除、搜索、分页、待完善和疑似重复提示。
- 切换“待完善”“疑似重复”“缺少主体”时，分类下方直接展示对应判定规则；无需额外展开，“全部客户”不展示规则卡片。
- 表头之后的非空记录不再因映射结果为空而被跳过。客户名称、公司名、邮箱任意一项为空时，单独进入“缺少主体”，提示实际缺项，保留原始非空单元格供查看、搜索和导出；完全空白的行仍跳过。
- 在“缺少主体”补齐三个固定字段后，勾选记录并点击右上角的“加入全部客户”。青蓝色实心按钮与新增、删除操作并列，显示可加入数量；批量操作仅加入所选记录中已补齐的部分，未补齐的继续保留。确认前保持在该分类，不计入全部客户、待完善或疑似重复；任意固定字段再次清空时，会重新进入缺少主体。
- 客户资料库可选择每页显示 10、25、50 或 100 条（默认 25 条），显示当前记录范围；切换数量、搜索或筛选时回到第一页，表头勾选只选择当前页。
- 青蓝色界面，统一线性图标；按钮提供悬浮变色与键盘焦点反馈，适配手机窄屏。
- 所有导入记录均保留原始非空单元格（含未映射列），可查看、搜索、导出，并在原始内容面板选取目标字段后填入；覆盖已有内容前先确认。
- 本地自动保存客户、字段配置、确认状态与最近一次删除记录，刷新或重新打开相同网址后恢复；显示真实保存状态和失败提示。
- 导出全部记录到 XLSX / CSV，附带来源、原始行号、校对提示、记录分类及所有记录的原始内容。
- 内置虚构示例数据及空白标准模板。响应式界面，保留工具名称 Banner。

## 使用

安装 Node.js 24 或以上版本后，在项目根目录执行：

```sh
npm ci
npm run build
npm start
```

浏览器访问 http://127.0.0.1:4173 。开发时使用 `npm run dev`，访问 http://127.0.0.1:5173 。本次重构已在本地下载依赖并生成 `dist/`；现有本地目录可直接双击 `start-local.cmd` 运行，详细步骤见 [LOCAL-SETUP.md](LOCAL-SETUP.md)。

构建后的网页需要通过本地 HTTP 服务访问，不能再直接双击 HTML 使用。运行时无需后端、账号、API Key 或第三方 CDN；构建与首次安装依赖需要相应工具，首次安装需要联网。

1. 导入文件，选择工作表和表头行。
2. 在导入面板核对自动映射，手动调整未识别的列，点击“添加到客户资料库”。多张工作表请分别添加。
3. 在“缺少主体”查看原始内容并补齐固定字段，勾选记录后点击右上角“加入全部客户”（可批量处理）；再按“待完善”“疑似重复”校对。最后导出客户表。

导出包含所有保留记录，不受当前搜索、筛选或分页影响。Excel 使用“客户资料”“缺少主体”两个数据表，并在有原始内容时附带“导入原始内容”表（每个原始非空单元格一行）；CSV 通过“记录分类”区分，并将原始内容保存在同一行的 JSON 文本中。所有导入记录均保留原始内容。导出文件不是完整工作项目备份，重新导入不会自动还原分组确认状态；本地自动保存会保留这些状态。

疑似重复仅提示，不会自动删除；同一来源的同一工作表不能重复添加。再次选择相同文件视为新来源，可能出现重复记录提示。

单击单元格编辑，点击表格外保存；邮箱、产品需求和备注使用多行编辑框。选择可跨页保留，表头复选框仅选择当前页；切换分类或搜索会清空选择，编辑导致记录移出当前筛选结果时也会取消对应勾选。删除前有确认，删除后可“撤销上次删除”，恢复该批记录的内容、确认状态和原始位置，不回滚其他客户的后续修改。仅保留最近一次非空删除；撤销信息也会本地保存。恢复遵循当前字段配置，已删除字段不会重新出现。新增、导入与撤销恢复均受 50,000 条上限约束。

## 客户资料库分类规则

切换到“待完善”“疑似重复”“缺少主体”时，页面自动展示该分类的检查范围、判定条件、计数或处理说明；没有匹配记录时仍显示规则。切回“全部客户”后隐藏规则卡片。规则展示与搜索、分页独立。

### 缺少主体与待完善

空白按去除首尾空格后的文本判断。“缺少主体”的条件是**公司名、客户名称、邮箱任意一项为空**；电话、需求或自定义字段有内容也不能代替固定字段。三项补齐后须勾选记录，并明确点击右上角“加入全部客户”，然后再按下列规则检查。导入时三项已齐全的记录直接进入全部客户。

“待完善”检查已加入全部客户的记录，目前仅有以下一条规则：

| 提示 | 判断条件 |
| --- | --- |
| 邮箱格式待核对 | 按中英文逗号（`,，`）、分号（`;；`）、中文句号（`。`）或换行拆分，再逐个用正则表达式验证，并检查每个邮箱的顶级域名格式；任意一项不通过就提示 |

英文句点 `.` 是邮箱本身的一部分，不作为分隔符，例如 `first.last@example.com`；多个邮箱可写为 `a@example.com。b@example.com；c@example.com`。校验逐项去除首尾空白，不改写保存或导出的邮箱文本。首尾或连续分隔符产生的空项也会触发提示，CRLF 视为一个换行，整段内容的首尾空白会先去除。

正则支持常见的无引号 ASCII 邮箱：用户名可含字母、数字、点和常见符号（如 `+`、`_`、`-`），点不能在用户名首尾或连续出现；域名至少有一个点，各段只允许字母、数字和内部短横线。单个邮箱最长 254 字符、用户名最长 64 字符、域名每段最长 63 字符。长度与基本语法参考 [RFC 5321](https://www.rfc-editor.org/rfc/rfc5321.html#section-4.5.3.1) 和 [RFC 1035](https://www.rfc-editor.org/rfc/rfc1035.html#section-2.3.4)。这不是完整的 RFC 地址解析器；中文等国际化邮箱、引号用户名、IP 字面量和带姓名的地址暂列为待核对，原始内容保留。

顶级域名检查每个邮箱最后一个英文句点后的部分：普通英文后缀必须是 2–63 个字母，忽略大小写，支持 `.com`、`.cn`、`.technology` 等长后缀，`.co.uk` 检查 `uk`；拒绝 `.c`、`.123`、`.c0m`、`.co-m` 等格式。`xn--` 国际化后缀还须通过浏览器的 IDNA 编码解析，最长 63 字符，且不会发起网络请求。规则参考 [ICANN 顶级域名技术说明](https://newgtlds.icann.org/en/applicants/global-support/faqs/faqs-en)、[IANA 国家代码规则](https://www.iana.org/help/eligible-tlds) 和 [WHATWG 域名转换规范](https://url.spec.whatwg.org/#concept-domain-to-ascii)。这是格式校验，不查询 IANA 委派名单或 DNS；例如纯字母的未知后缀仍可能通过，不能据此判断域名已注册或邮箱真实可用。

固定字段缺失统一归入“缺少主体”，不再计入待完善。邮箱有内容但格式异常不会阻止加入全部客户，加入后列为待完善；多个邮箱中任意一个格式异常就触发提示。电话、国家、产品需求、网站、备注和自定义字段为空不触发待完善；疑似重复另行提示。当前不验证电话格式、电话真实性、邮箱可投递性或客户真实性。“可用”仅表示通过现有基础检查。

### 疑似重复

- 跨来源、跨工作表比较已加入全部客户的记录，缺少主体不参与。
- 使用邮箱校验的相同分隔符逐个拆分。两条记录只要有一个共同的有效邮箱，就提示疑似重复，邮箱顺序和分隔符不影响结果。
- 仅域名忽略大小写；用户名保留大小写、句点、短横线、下划线、加号等有意义字符，不做邮箱服务商特有的点号或别名合并。该保守规则参考 RFC 5321 的邮箱本地部分语义。
- 无效邮箱不作为重复依据；包含无效项的记录，其余有效邮箱仍参与。不会只因公司或姓名相同就匹配。
- 同一记录内重复写一个邮箱不计为重复客户；涉及共同邮箱的全部记录各计一次，不是重复组数。疑似重复仅提示，不自动合并或删除；同一条记录可以同时是待完善。

`a-b@example.com` 与 `ab@example.com` 不会被误合并；`sales@example.com;buyer@example.com` 与 `buyer@example.com` 会提示重复。共用邮箱可能对应不同联系人，仍需人工判断。

### 字段设置

字段设置随客户数据自动保存在当前浏览器，即使尚无客户也会保存。建议先设置字段再导入；已有客户新增字段时初始为空，可手动填写，或从原始内容面板填入。删除包含数据的字段会先确认，确认后移除该字段内容及所有文件中的对应映射，导入时的原始单元格仍保留。字段名不能为空、重复或使用系统列名，最长 30 字符，总数上限 40。“固定字段”不可删除，且加入全部客户前必须全部填写。

## 数据与边界

客户数据在浏览器内处理，不向服务器上传。IndexedDB 保存已加入资料库的全部记录（包括缺少主体）、字段配置、确认状态、原始内容与最近一次删除记录。仅在存储事务成功提交后显示“已保存到本地”；保存失败支持重试，不会因导出成功就误认为本地保存成功。尚未保存时离开页面会提示。恢复失败或数据格式无法识别时停止自动写入，保留已有存储。

本地进度属于当前设备、浏览器配置与网址；线上、本地预览、不同端口的数据彼此独立。清理网站数据、无痕窗口结束或浏览器回收空间可能移除进度。此版本不提供账号、云同步或跨设备恢复。原始工作簿及尚未加入资料库的导入映射不持久化，刷新后需重新选择文件；已经导入的原始单元格和字段配置不受影响。旧版本未保留的原始列不能凭空恢复，需要重新导入源文件。

多个页面通过存储版本校验防止旧页面覆盖新进度；出现冲突时暂停本页自动保存，保留页面中的修改供导出，提示重新打开加载最新进度。设置最多 50,000 条客户记录，大文件建议分批处理，这不是性能保证。密码保护文件需要先解密。

电话以显示文本读取并以文本导出，保留原表已有的前导零和国际区号；原文件中已丢失的信息无法还原。CSV 为防止公式注入，对公式前缀添加单引号；XLSX 输出文本单元格。源公式只读取已有显示值，不执行宏和公式。

## 技术与验证

React 19.3.1、Ant Design 6.6.6、AG Grid Community 36.2.0、TypeScript 7.0.2、Vite 8.3.4；实际依赖由 `package-lock.json` 锁定。仅使用 AG Grid 免费社区版功能，Excel 导入和导出继续使用本地内置 SheetJS CE 0.20.3（Apache-2.0）。

数据规则在 `src/domain/core.ts`，会话状态转换在 `src/state/workspace.ts`，文件处理在 `src/services/workbooks.ts`。界面按职责拆为独立组件。表格采用虚拟渲染，编辑提交后统一更新状态；分类统计随记录变化缓存，搜索或翻页不重新计算重复组。

```sh
npm test
npm run build
```

自动化测试覆盖原有规则、Excel/CSV 数据保留、顶级域名边界、多邮箱匹配、隐藏选择、删除恢复、IndexedDB 完整恢复、串行写入、保存失败重试和多页面写入冲突。浏览器验证使用虚构数据，不读取真实客户资料。

`dist/` 是自动生成的构建产物，不再提交到 Git；源码与依赖锁文件提交到仓库。GitHub Pages 的手动工作流会安装依赖、测试、构建，再发布 `dist/`：先在 Settings → Pages 中选择 GitHub Actions，再在 Actions 运行 Deploy static site。线上 Sites 保留原项目身份和访问权限。
